# 原生书源真机验证步骤与记录

初版：2026-11-08；更新：2026-11-09。对应 P1-06/P1-07、D02/D03/D10。已有离线示例、本地联网源及安装/功能预览正常的用户反馈；最新反馈没有绑定具体提交、设备或系统版本，详见 [P2 报告](reports/SOURCE_PROTOCOL_P2_REPORT.md)。本表只列仍需补充的设备证据。不得将模拟器成功代替真机性能或硬终止验收。

## 准备

1. 安装包含待验收改动的 GitHub CI IPA，记录实际构建提交、文件名/摘要、App 版本、设备型号、iOS 完整版本、电量/低电量模式、网络类型。保留现有本地书源即可，不上传网站专用源或正文。
2. 打开「设置 → 其他设置 → 书源协议实验室」。离线示例先执行四项操作一次，作为恢复基线。
3. 资源测量需要连接 macOS 的 Xcode Instruments，记录 App 与相关 WebContent 进程总内存、CPU、能耗；只有 Windows/iPhone 时仍可记录 UI、取消、前后台与恢复现象，但内存/能耗栏保留“未测”。

故障源没有 search 入口；选择 content 并使用输入 `{"book":{"id":"fixture-book"},"chapter":{"id":"ch-1"}}`。这些故障操作不访问 metadata 中的 loopback 地址，真机不需要连接本地 fixture 服务。

| 场景 | 步骤 | 应记录的结果 |
| --- | --- | --- |

| 用户取消 | 运行上面的等待源后点取消；再切回离线源 | 是否只出现一个终态、是否还能开始新操作；原生网络取消另由 CI fixture 验证 |
| 前后台 | 普通离线操作和等待操作分别切后台再回来；各重复三次 | 是否重复结算、界面卡死或恢复后无法执行；记录后台停留时长 |
| 同步无限循环 | 单独一次使用 `runtime-faults/infinite-computation.source.js` 的 content；不要放入自动批量流程 | UI、deadline、WebContent CPU、总内存、新页面是否受牵连；必要时手动退出 App，记录是否必须重启才能恢复 |
| 内容进程异常 | 有 macOS 调试设备时做受控 WebContent 进程终止；仅 Windows 环境此项保留待测 | RUNTIME_TERMINATED 是否可见、旧回调是否失效、下一正常操作能否恢复 |
| 持续运行资源 | 同一普通源重复运行并在成功/取消后观察 30 秒，再重复三轮 | App + WebContent 总资源趋势；系统缓存不能误记为泄漏，需比较稳定阶段 |

## 封面与分类诊断复核（2026-11-09）

- 搜索/书架/详情中的封面应保留宽高比；加载失败显示占位，正文仍可打开。确认大量结果快速滚动、切换账号或修改选项后没有串图，离开页面取消在途请求。
- 同一安装和账号下，已缓存封面重开可见；正常 24 小时后尝试更新，网络失败可使用同身份旧缩略图。超过 128 张或 32 MiB 会自动回收，封面缓存不属于永久离线下载。
- “缓存与下载 → 清理封面缓存”只清理缩略图。清理中尚未完成的下载不得重新填充，随后主动重开仍可下载。
- 受控书源分别返回认证、限流、解析错误、空结果和正常结果；页面应区分失败与空结果。认证入口打开该书源账号设置；限流等待后手动重试；源码/目录失效提示能指导恢复。
- “书源诊断”应记录操作类型、错误码和耗时；使用含虚拟敏感字符串的合成错误检查导出 JSON，不应出现网站 message、URL、查询词、账号明文或正文。重启 App 后内存诊断为空。
- 使用新构建完成已有 TXT 的目录/阅读/翻页/进度重开，以及 EPUB 的图片/表格/出版样式/locator 恢复。模拟器新增既有本地阅读器回归，实际 iPad 分屏与手势仍需设备记录。
