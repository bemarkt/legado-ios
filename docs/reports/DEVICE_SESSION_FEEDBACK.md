# 网站会话与失败响应入口修复

日期：2026-11-09。源码版本：0.1.18 (24)，尚未构建 IPA。Cookie/诊断/响应入口修复已通过核心、App 编译与实际 WebKit 回归；真实网站仍需设备复测。按用户最新要求收尾并暂停，不再启动新包，见 [阶段暂停检查点](PROJECT_PAUSE_CHECKPOINT_2026-11-09.md)。

## 用户反馈与证据

用户报告：刷新目录失败后，“查看失败响应”先误开书源设置；关闭后才能看到响应。打开失败网页验证并保存登录，目录暂时恢复，正文仍失败，退回书架再进目录又失败。

本次私有诊断包含 4 次目录成功、4 次 EMPTY_CATALOG、1 次 EMPTY_CONTENT；失败均为 HTTP 202 / 209 字节，另有 8 次封面成功。没有实际发出的 Cookie 信息，不能从旧诊断断言完全未带 Cookie，也不能证明网站当前验证机制。私有书源、原始诊断和网站响应不入 Git。

## 实现范围

1. **保留 Cookie 域。** 原实现把父域和主机同名同路径 Cookie 压成一个保存键，并丢弃 Domain。现在按授权 origin、有效 cookie domain、name、path 区分，浏览器重新注入保留域；Domain 等于当前主机时与 host-only 共用 cookie 身份。HTTP 删除只匹配对应域。解码也进行校验，旧记录缺少 Domain 时仍按原精确 origin 使用，不猜测更大的授权范围。
2. **会话更新可持续。** 服务器更新已由浏览器明确保存到多个获准 origin 的父域 Cookie 时，同步这些已有副本，写入持久凭据库。普通轮换不改变登录代次；不会仅因 Domain 自动创建其他 origin 的授权副本。
3. **记录实际发送情况。** 诊断取最终附加凭据后的请求，记录发送 Cookie 对数、响应解析及删除数量、Set-Cookie 是否存在、状态、字节数与网站/UA 摘要。每个操作最多保留末尾 16 次 HTTP 交换，含重定向；普通导出最多 128 个操作 / 1 MiB，不含原始凭据、Cookie 名值、URL、响应文本或原始登录代次。无 HTTP 响应的传输失败不会伪造一条交换。
4. **一个操作只打开一个页面。** 失败区不再在同一 Form 行放多个 NavigationLink；各按钮独立响应，由一个 item 决定唯一 sheet。响应页内仍能打开验证网页。

旧版本已经丢掉的 Domain 无法从保存记录恢复，安装新版本后需在验证页重新保存一次登录。这是迁移边界，不清除已有书籍、缓存、进度或旧凭据。

## 保留的设备复测顺序（恢复实施并有匹配包后）

1. 失败后点击“查看失败响应”，应直接出现响应详情。
2. 在“打开此页面验证”中完成验证并保存一次登录，退出该窗口。
3. 刷新目录并读取未缓存正文，返回书架后重进，再刷新、读另一章；重启 App 后重复。
4. 若仍失败，查看失败响应中的实际发送 Cookie 数量、响应更新/删除数；导出新诊断，比较成功和失败请求的网站、UA、登录代次摘要。Cookie 数大于零只证明附带了 Cookie，不证明其有效或满足网站验证。
