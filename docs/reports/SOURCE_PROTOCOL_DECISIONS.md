## 决策修改规则

### 2026-11-09：D02/D05 登录边界与账号含义修正（实施中）

账号指网站登录状态，不应成为本地书架分区。后续实现将稳定本地书籍身份与可撤销的网站会话分开，保留旧数据；认证请求、脚本状态与在线缓存继续按会话校验，不能因书架统一而复用另一登录状态的结果。原“本地账号各有独立书架”不再作为产品目标，既有测试需随模型迁移一并调整。

用户主动打开的网页登录使用独立临时 WKWebView，无 sourceHost 桥；允许普通 HTTPS 网站资源、重定向和身份服务，以避免单 origin 限制造成空白。源代码执行和原生 HTTP 仍受安装的已授权 origins 约束；仅导出匹配这些 origins 的 Cookie，不扩大授权，也不导出无关身份服务 Cookie。普通外部 HTTP、下载与原生自定义 scheme 不在此浏览器支持范围；loopback HTTP 只用于测试。

旧 JSON 的字面量 loginUrl（含相对路径）和静态 header 用于实际登录请求；脚本登录地址、URL 请求选项及动态 header 明确拒绝，不借用旧全局运行时。当前不是完整 OAuth 弹窗、loginUi/loginCheckJs 或通用动态正文引擎。HTTP 202 空壳只证明一次本机未登录响应，不能据此断言真机失败全由 Cookie 导致。

候选改变时同时更新协议文字、Schema/profile、类型、例子与对应测试。只修改实现不更新合同，或只改通过线不记录依据，均不能关闭决策。运行时选择不得把 Node 成功当成 WebKit 证据。

D01–D10 均未标记最终关闭。当前已有 P2/P3 实验实现与自动化证据，未决项按表中范围补证；未最终关闭不代表整项功能尚未实现，也不能把设备缺证据记为已知行为失败。

### 2026-11-09：D07 诊断可见性与本机数据边界

76cd7f2 的设备记录只有 EMPTY_CATALOG / 202 / 209 字节，不足以定位网站返回内容。因此 abb38ab 将有限导出摘要和本机响应检查分开：失败操作 UUID 对应准确源码摘要，最近 8 份、每份 64 KiB、15 分钟可查询的响应只留内存；清除同时删除。展示最终地址、Content-Type 和供规则解析的文本，不保留其他头，HTML 不执行。原有诊断 JSON 不增加正文、地址或凭据；响应类型不实现 Codable，避免被普通报告误编码。打开验证页仍校验已授权 origin，并重新使用当前网站会话；不自动重试或扩大旧源权限。

离线选项属于本地书籍偏好，迁移标记仅提供未选择时的默认值。书源编辑弹窗以完整、不可变的 request 携带内容，避免状态触发先于文本到达。这些修复的自动化与实机验收分别记录在 [设备反馈报告](DEVICE_FEEDBACK_76CD7F2.md)，不改变发布条件。

P1 当前交付及 CI 证据单独记录于 [P1 报告](SOURCE_PROTOCOL_P1_REPORT.md)。资源上限不因原型可运行而自动成为发布承诺。

P2 阅读/账号/封面集成见 [P2 报告](SOURCE_PROTOCOL_P2_REPORT.md)，P3 调试与更新恢复见 [P3 报告](SOURCE_PROTOCOL_P3_REPORT.md)。

## 2026-11-09：D08 验证策略调整

原因：当前产品面向 iOS，自有协议不以 Android 行为定义；为少量离线规则维护整套 Android 构建已经产生环境修复成本。保留参考实现与已有探针，采用可追溯预期、Swift 回归和 iOS 完整链路作为限定范围功能验收，具体歧义再作 Android 对照。

影响：调整 P0 环境依赖、P4/G4、测试矩阵与工作顺序；不降低真实阅读、账号、取消和恢复的证据要求，不把未运行的差分记为通过。持久预期与无 Android 的自动回归接线已在 01d58e6 CI 通过；生产兼容集成已通过 4c52079 常规 CI 与实际 iOS 套件；限定矩阵见 P4 报告。重新评估条件为出现两端具体回归、参考版本语义变动，或产品需要承诺指定 Android 行为一致。
