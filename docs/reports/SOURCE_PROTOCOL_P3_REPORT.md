## 运行错误到对应源码

- SourceRunner 从错误栈提取该次 blob 模块的有限行列，只返回位置，不记录/导出完整 stack 或 URL。支持 CR/LF/CRLF/Unicode 行分隔；列按 1 起算 UTF-16 单元。对恶意异常属性和越界位置降级为无位置错误。
- 诊断页依据宿主源码摘要查找当前安装和最多 8 个历史版本；只有字节摘要匹配才显示片段。旧版本被淘汰时明确提示，不替换为当前源同一行。
- 片段最多 5 行，每行最多 500 个 Swift Character；长行标省略。操作和位置可带到实验室查看文件并手动重试；不复制查询词、凭据或 storage，不自动执行源。
- 行列是作者错误对象给出的调试线索，不能当作权限或身份凭据；源码身份仍由宿主摘要确定。当前不是带断点/暂停/单步的通用 JavaScript 调试器。

## 可选构建映射

构建器使用 MagicString 保留元数据抽取/缩进/包装的映射，再与 esbuild map 组合。普通 .source.js 与生成 map 时的 .source.js 字节相同，成品仍可独立分享、修改和运行。可选 sidecar 不内嵌原始源码、不写 sourceMappingURL；map 中只保存相对路径与输出摘要。

locate-source 命令读取有界 UTF-8 源文件和 map，先核对摘要，再还原原始 TS/依赖位置；不读取映射引用的文件、不联网、不执行代码。修改源码、部分文件写入或错误 map 不能产生看似有效的旧定位。生成包装行无映射时保持无原始位置。相对路径仍可能含目录名，映射不默认分享；跨盘符无法相对定位时拒绝输出。

macOS 首轮暴露 /var 与 /private/var 符号链接别名导致的错误相对路径；修复使用真实入口和输出目录，补符号链接回归。首轮失败 42540967823 停在 Node 检查，未执行 WebKit，不能记为运行环境失败或通过。

SourceRunner 从 tools/source-protocol/browser/runner.mjs 和共享 error-location 模块构建，npm run check 同时验证 App 内嵌文件是否漂移；不再分别维护两份位置提取逻辑。

## 构建源的 WebKit 对照

受控 loopback fixture server 仅构建仓库自造的 docs/examples/source-project，执行该固定样本的 Node 搜索/详情/目录/两章正文，提供编译源码、摘要、预期结果和已知失败位置。它不接收任意作者代码路径。Swift 测试在全新 WebKit 页中分别执行相同操作，并验证普通 throw、顶层 throw、类型化 PARSE 错误及 provider 诊断。

Node 的输出比较证明这些样本的行为；实际 DOM/网络仍由既有 HTML/JSON WebKit 测试覆盖，不把无网络样本扩张成所有构建源兼容承诺。

## 更新恢复证据

上一轮 39aa26b 已覆盖配置、历史、活动源码三个写入点的 ABORT/ROLLBACK，确认失败后的整个旧状态、显式重试与账号配置重新审阅。新 SourceRecoveryProbe 是仅用于 SwiftPM CI 的可执行程序，不加入 iOS target。

父 Python 进程在专用临时目录创建近源码上限、满历史队列和两个账号的数据库；子进程调用真实 SourceArchive.saveInstallation。分别在更新前、事务期间、commit 后 SIGKILL，再用新进程重开：只能完整旧状态或完整新状态，账号选择/网站 state/书架不受影响；中断后显式重试应成功。

第一次中途测试 9a92d8e / 42540975467 因五次都在提交完成后才观察到 WAL 变化而失败；没有把新状态误判成中途通过。修复在合成数据库安装触发器：真实 history 更新触发未提交的大块写入和有限 SQL 计算，父进程观察 WAL 增长后结束子进程。触发器只在测试库存在，重试前移除；没有向产品代码加入暂停钩子。该修复在 42541410078 的实际 macOS 子进程上通过：before/during 恢复完整旧状态并成功显式重试，after 恢复完整新状态；during 观察到未提交 WAL 增长，三者 integrity_check 均为 ok。报告在 build/github-actions/c3af1d0/core-artifacts/build/source-process-recovery.json（以下载目录实际结构为准）。此证据不替代硬件断电、磁盘满、iOS 文件保护/后台终止或真实设备恢复。
